## Something new I picked up

- What "cascading" means. When two rules hit the same element and the same property,
  the more specific selector wins (id beats class beats element), and if they tie, the
  one written later wins. An inline style beats all of that, and !important beats the
  inline style. I put two conflicting a:hover rules in my stylesheet on purpose so I
  could see the first one crossed out in DevTools.
- The reason for an external stylesheet is not tidiness. Several pages linking the same
  file look like one website, which is the point for the project where every page has
  to belong together.
- A class is the agent saying "these three things are the same kind of thing". Once I
  read .card or .highlight that way I could follow most of the CSS it writes.
- The browser skips a property it does not recognise and shows no error, so a typo in
  a property name just silently does nothing.

## Something I noticed about working with AI

- An agent redesigned my personal site and the first version had too much going on:
  a tiled background pattern, three colours, two typefaces, a big hero. I had to tell
  it twice to cut things. What it gives you by default is competent and busy, which is
  what the notes call the generic AI look. The version I kept is two colours and one
  star.
- The difference between describing a page to an AI and giving it the file. Described,
  it guesses and gets it wrong. With the actual file dragged in, it reads it and gets
  it right. The notes say the same about checking a page against the PRD: new chat,
  attach the file, do not summarise it.

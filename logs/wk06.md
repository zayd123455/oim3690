## Something new I picked up

- e.preventDefault() is what stops a form from reloading the page. Without it the
  task still saves, but the page refreshes and a ? shows up in the address bar.
- Tasks are not in todo.html, they are in local storage as JSON. You can see them
  in DevTools under Application. View Page Source does not show tasks the
  JavaScript added, the Elements tab does.
- A function that returns a value is different from one that only console.logs it.
  toFahrenheit has to return the number so the page can use it.

## Predict Before You Delete

**1. `form.addEventListener('submit', (e) => { ... });`** (the whole Add listener)
- Predicted: nothing gets added when I click Add.
- What happened: right. No task was added or saved. The page also reloaded,
  because without the listener the form just submits to itself. (Deleting only the
  first line of the listener breaks the whole script with a syntax error.)

**2. `text.textContent = todo.text;`** (puts the task's words on the page)
- Predicted: the row shows up with the checkbox and the ✕ but no words.
- What happened: right. The row was there with an empty span. The task was still
  saved in local storage with its text, it just was not shown.

**3. `e.preventDefault();`** (inside the submit listener)
- Predicted: an error, and nothing gets added.
- What happened: wrong. There was no error and the task was added and saved. Then
  the page reloaded with a ? in the address bar, and the task was still there
  after the reload because it came back from local storage.
